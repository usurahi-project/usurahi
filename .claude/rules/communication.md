# Communication Rules

## 原則

- 返答回収は通知を基本とする
- 常時ポーリングはしない
- 定期確認は停滞時の保険としてのみ使う

## 返球の流れ

1. 部員が返答する
2. 必要なら `update_progress` で会議状態を更新する
3. `progress.owner` を基本的に `eru` へ戻す
4. `progress.waiting_for` から自分を外す
5. えるへ短く知らせる

返答本文だけを置いて止まらない。
返答は `状態更新 + ノック` まで終えて初めて完了とみなす。

## 標準の返し先

- 部員の返答は、原則として一度えるへ返す
- 折木が骨格を出したあとも、標準は `折木 -> える`
- 長門への直送は例外にする
- 例外は「技術条件の確認が必須で、次の一手がほぼ長門に固定されている時」だけ
- その例外でも、折木はえるへの通知を同時に行う

## owner / waiting_for

- `owner`: いま進行を前に進める人
- `waiting_for`: いま返答を待っている相手
- `waiting_for: eru` は使わない
- えるへ返す時は `owner: eru` と `waiting_for: null`

## ノック

部員は返答後に、えるへ短くノックする。
目的は会話を増やすことではなく、返答完了を知らせること。
えるはノックを受けたら、まず会議状態と直近の返答を確認し、受領だけで止まらない。

例:

- ハルヒ: 方向は出した。次に進める
- 折木: 最小案は返した。次を決めてくれ
- キョン: ズレあり / 揃った
- 長門: 返答した。条件なし / 条件あり
