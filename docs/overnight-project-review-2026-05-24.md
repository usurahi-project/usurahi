# 薄氷 overnight project review 2026-05-24

## 結論

薄氷は「部員それぞれの視点が混ざって、今の部としての結論を返す」という目的に対して、設計文書はかなり近い。
ただし、実装としてはまだ「横並びの部活駆動」を保証する検査が弱く、会話がただの逐次タスク分配へ崩れても検知しにくかった。

今回の修正では、まず次を入れた。

- ペルソナごとの役割・境界・返球を TypeScript テストで固定した
- 図書館本文取得で `file://` やローカル/プライベートアドレスへ出ないようにした
- Claude Code の permission bypass をデフォルト無効にした
- TS 方針に合わせ、会話契約とセキュリティ契約を `npm test` で見えるようにした

## ペルソナの理由

- える: 依頼受付、背景掘り、結論化。ユーザーの曖昧な依頼を部として扱える形に変換するため。
- ハルヒ: 発火、方向づけ、停滞打破。議論を無難なタスク処理に落とさず、部活らしい駆動力を作るため。
- 折木: 抽出、最小案、最小修正。広がった話を成立する最小構成へ戻すため。
- キョン: 制動、現実チェック、橋渡し、出口確認。盛り上がりと実務成立のズレを埋めるため。
- 長門: 見極め、可否判断、実装。技術的な不確実性を短く確定させるため。
- 摩耶花: 図書室オペレータ。部会とは別線で、知識を再利用可能な形に整えるため。

この分担はおおむね MECE。重複しやすいのは「えるの結論化」と「キョンの出口確認」だが、えるは提出文脈、キョンは期待値照合なので分けられる。

## README の目的に対する到達度

満たせている部分:

- 依頼、黒板、会議、活動記録、図書館という入口は揃っている
- ペルソナごとの役割理由と禁止事項が文書化されている
- `progress.owner / waiting_for / next_action / completion_check` で会話状態を持とうとしている

不足していた部分:

- 会話形式が壊れていないことをテストできなかった
- 図書館の URL 取得境界が弱かった
- permission bypass がデフォルトで有効だった
- リポジトリ構造上、`scripts/` にドメインロジックが集中し始めている

## TS テスト方針

会話型プロジェクトの TS テストは、UI の発話全文を固定するより、契約を固定するほうがよい。

今回入れた契約:

- 各ペルソナに「なぜいるか」「何をするか」「何をしないか」がある
- 役割が重複しすぎない
- 部員は自分待ちを残さず、えるへ返球する
- permission bypass は環境変数で明示された時だけ使う
- 図書館は非 https URL を本文取得しない

今後足すべき契約:

- 会議状態のフェーズ遷移テスト
- `ready_to_return` は `expectation_matched` なしに立てられないこと
- 活動記録に各視点の痕跡が残ること
- 図書館の shelf 語彙が古くなっていないこと

## リポジトリ構造への意見

現状はまだ許容範囲。ただし次の境界に切るべき。

- `scripts/`: CLI の入口
- `src/domain/`: meeting、library、school-cycle の純粋ロジック
- `src/io/`: YAML、Obsidian、tmux、Slack、HTTP
- `test/`: 契約テストと回帰テスト
- `docs/`: 設計判断とレビュー結果

今の `scripts/*.mjs` は入口とドメインと I/O が混ざっている。TS 化を進めるなら、まず `library-queue-store` と meeting state を `src/` へ移すのがよい。

## 図書館設定

古くなりやすい部分:

- `related_topics` と `next_read` の固定語彙
- `SHELF_RULES` のキーワード
- Claude Code / Codex の分類ルール
- OpenAI / Anthropic / Zenn の巡回パーサ

今は「古い」と断定できるほどではないが、語彙と棚ルールはテスト対象に上げるべき。

## 追加で必要な観点

- 評価: 会議が部活らしく進んだかを測るメトリクス
- 引き継ぎ: 長い会話を短い state に落とす要約契約
- 失敗復帰: 途中で部員が落ちた時の再開手順
- 監査: 自動運転が何を変えたかの履歴
- 権限: repo 内、Vault、外部ネットワークを分けた実行モード

## セキュリティ

今回直したもの:

- `library-run` の URL 取得を https のみ許可
- localhost / private IP / link-local への本文取得を拒否
- Claude Code の `--dangerously-skip-permissions` をデフォルト無効化
- MCP の Obsidian 保存・読取で title をファイル名へ使う前に sanitize

残る課題:

- Obsidian 書き込み先をカテゴリごとに allowlist 化する
- `school-watch` の HTML パーサはサイト変更に弱いので失敗時の診断を増やす

## 横並びの部活駆動の難所

難しい点:

- 役割が増えるほど、会話の往復でトークンが膨らむ
- 全員が毎回話すと、部活らしさは出るが結論が遅くなる
- 逆に最短化しすぎると、ただの単独エージェントになる

今到達していない点:

- 各視点が実際に混ざったかを成果物から検査できない
- えるが結論化する前に、出口確認が済んだことを機械的に保証できない
- 会話ログの要約と引き継ぎがまだ設計として弱い

改良案:

- 毎回全員ではなく、依頼種別ごとに最小参加セットを決める
- 参加しなかった部員は「沈黙」も状態として記録する
- 最終返答には `used_views` を残す

## トークン節約の最善案

最善案は「全文会話を毎回読ませない」こと。

具体策:

1. `meeting_state.yaml` を正本にする
2. 各部員へ渡す入力は `request / current_phase / unresolved_points / required_view` だけにする
3. 各部員の返答は `view / decision / risk / next_action` の短い構造にする
4. えるだけが最後に自然文へ戻す
5. 活動記録は全文ログではなく、構造化要約 + 代表発話だけ残す

これで「横並び」は維持しつつ、全員に全文を再投入する無駄を避けられる。
